# 家庭助理操作

首頁直接輸入需求，或點「開冷氣 1 小時」「安排洗衣」。助理提出計畫後，在同一張卡按確認；運轉狀態、修改、取消與停止也都在卡片上。兩台設備分別確認。

範例：「幫我開冷氣，順便幫我安排洗衣。」不用先選設備或填寫日期表單。

## 預設與確認

- 冷氣：27°C、舒適範圍 26–28°C、運轉一小時。未指定開始時間時，卡片顯示「確認後開啟」，確認當下重新讀取室溫及計算起訖，依計畫自動關機。明確指定的預約時間維持固定。
- 洗衣：24 小時內完成、避開 23:00–07:00、選預估費用較低的合法時段。明說「現在洗」時優先選最早合法時段。
- 「修改計畫」直接輸入新需求。尚未啟動的舊計畫會先暫停，避免助理規劃時仍照舊啟動；修改不建立第二個同設備任務。
- 冷氣「關閉冷氣」與洗衣「停止洗衣」會先顯示確認，再送出中止；必須取得設備回報才算停止。
- 快捷按鈕與文字走相同 Main／子 Agent 流程，不跳過核准。沿用 vLLM 主用、Azure 備援；沒有另外新增離線替代流程。

輸入框下方直接顯示目前偏好。左側「偏好與進階設定」可儲存溫度、運轉分鐘、洗衣期限及安靜時段，只影響新計畫。快捷「開冷氣 1 小時」明確指定一小時，文字「開冷氣」則使用儲存的運轉分鐘。

## 設備與進階設定

「冷氣」「洗衣機」「用電紀錄」用來查看設備、手動預約與圖表，主流程的核准不需要切換分頁。原洗衣手動操作保留在可展開區域內。

費率、每月基準、時間倍率與工具紀錄收在左側進階設定。基準改為選月份、輸入度數，保留其他月份，不用手填 JSON。正式費率缺少基準時仍停止正式估算，不會自行換成模擬費率。

模型在背景處理，畫面不直接呼叫模型或設備。對話從 SQLite 的需求、事件與執行紀錄還原，重繪或重新開啟網頁不會重送需求；處理中停用重複提交。原有版本、核准、Matter 與未知狀態保護繼續適用。

使用原來的 `scripts/start.ps1 -Transport mqtt|matter`。本次改版另以隔離的 8505 環境驗收，原任務資料庫保留；該環境停止指令為：

```powershell
.\scripts\stop.ps1 -RuntimeDirectory artifacts/ui-redesign/runtime
```
