## 5. 優先缺口

以下前兩項及第四項為程式靜態檢查結果；第三項是驗收覆蓋缺口。

1. **助理計畫卡資訊不完整。** `App.tsx` 的 `ProposalCard` 只顯示設備、狀態、用電與費用，未列出日期／起訖、冷氣目標、洗衣限制與核准範圍。舊操作文件要求使用者在核准前能檢查這些內容，設備抽屜已有較完整資訊可供共用。
2. **待核准修改入口與版本更新後操作需收尾。** `approvable ? null : 修改按鈕` 使可核准的 pending 計畫隱藏修改按鈕；卡片又以事件原始版本與最新版本完全相等作為操作條件。需提供明確的目前版本入口，驗證核准／修改後仍可追蹤與管理任務，並保留過期版本不可核准的保護。
3. **現有通過測試不等於 CopilotKit 完整 UI 驗收。** `controls.test.tsx` 模擬掉 Sidebar 與 `useRenderTool`，實際計畫卡沒有被測到。`test_assistant_service.py` 有終態事件從頭重播測試，尚未涵蓋帶游標續接、Runtime 在工作中重啟、worker 完成邊界中斷，以及新版瀏覽器重整／雙頁的完整流程。
4. **燈泡新目標替代舊目標與計畫有差異。** 舊燈泡計畫要求新明確操作能取代未完成目標；目前 `BulbController.process_requests()` 在有 active action 時先等待。需補明確的取代／優先規則與測試，尤其自動規則加入後，手動指令不能被較舊的自動目標蓋回去。
5. **文件與版本資訊分散。** 部分指南仍寫左側設定、SQLite v2 或只有 Matter 端點 2／3；目前為頂部設定、SQLite v4、端點 2／3／4。套件 metadata 為 0.1.0，Changelog 為 v1.3.0；需說明版本政策並記錄遷移交付。
